PHP · CVE-2026-109618 und -109619

PHP2Shell: Fremder Code mit einer einzigen Anfrage

Was ist passiert?

17.10.Amazon sieht den ersten Angriffsversuch auf seinen Lockvogel-Servern, 4 Tage vor der Veröffentlichung
20.10.Die Nummern der Lücken sickern auf Social Media durch. PHP zieht das Update um einen Tag vor.
21.10.Updates erscheinen: 8.5.12, 8.4.27, 8.3.36, 8.2.35
seitherAngriffe von mehreren Gruppen, Cloudflare blockt erste Attacken

Gefunden von Calif, mit Hilfe von KI-Modellen. Der Fehler steckt seit PHP 5.4 (2012) im Code.

Der Fehler

  • Ein präpariertes Formular (z. B. ein Datei-Upload) bringt PHP dazu, den Arbeitsspeicher zu sprengen
  • Beim Aufräumen benutzt PHP dann halb fertige oder schon freigegebene Daten
  • Der Angreifer kann so eigenen Code auf dem Server ausführen, ohne Login

Wen es trifft

Jeden Webserver mit PHP: WordPress, Drupal, Joomla, Magento … Geschätzt über 1.3 Mio. Server im Internet. Schweregrad 9.2 von 10.

Quellen: Tenable PHP2Shell FAQ, Rapid7, Google Cloud (22.10.2026)
Zwei Fehler zusammen: Beim ersten geht PHP mitten im Aufbau einer Anfrage der Speicher aus, und das Aufräumen arbeitet mit unfertigen Daten. Beim zweiten zeigen Reste der vorherigen Anfrage auf Speicher, der schon freigegeben ist. Die nächste Anfrage im selben Prozess liest diese Reste. Wichtig: Der Angriff passiert, bevor überhaupt WordPress-Code läuft. Darum hilft ein WordPress-Update nichts.

PHP · So beheben wir es

Nicht WordPress updaten, sondern PHP selbst

  Auf unserem Mac

php -v
PHP 8.5.9 (cli)
betroffen 
brew upgrade php
php -v
PHP 8.5.12 (cli)
sicher

Auf dem Laptop läuft PHP nur im Terminal, nicht als Webserver. Das Risiko ist klein, das Update trotzdem machen.

  Auf einem Webserver

  • PHP über den Hoster oder apt upgrade aktualisieren
  • Danach PHP-FPM bzw. Apache neu starten, sonst läuft die alte Version weiter
  • Ein WordPress- oder Plugin-Update hilft nicht: Der Fehler liegt eine Ebene darunter
PHP 8.1 oder älter? Gibt es keine offiziellen Updates mehr. Die US-Behörde CISA rät, solche Server vom Netz zu nehmen, bis sie aktualisiert sind.
Notlösung, falls ein Update nicht sofort geht (nur abschwächend): session.upload_progress.enabled=0, bei 8.5 zusätzlich fatal_error_backtraces=0
Homebrew hatte am 23.10. bereits 8.5.12. Auf Servern: Neustart nicht vergessen, sonst läuft im Speicher immer noch das alte PHP. Die Konfigurations-Tricks verkleinern nur die Angriffsfläche, sie ersetzen das Update nicht.

Node.js · CVE-2026-111497 und 9 weitere

Node.js: Ein Fehler beim Entpacken komprimierter Daten

Fremder Serverschickt eine präparierte Antwort
Brotli-komprimiertContent-Encoding: br
Node.js entpacktz. B. bei fetch()
Schreibt über den Randdes Speichers: fremder Code läuft

Was ist passiert?

21.10.Node.js veröffentlicht 10 Lücken auf einmal, 4 davon schwer
fix26.12.1, 24.22.1, 22.23.4
EOLNode 20 und älter bekommen kein Update mehr

Den Brotli-Fehler hat OpenAIs KI-Werkzeug Codex Security gefunden.

Brotli?

Ein Format, mit dem Webserver ihre Antworten verkleinern, ähnlich wie ZIP. Node.js entpackt solche Antworten automatisch. Ein präpariertes Paket bringt den Entpacker dazu, über das Ende seines Speichers hinaus zu schreiben.

Weitere Lücken: Die TLS-Prüfung lässt sich mit IP-Adressen austricksen, dns.resolve schneidet Namen ab.

Quellen: nodejs.org «October 2026 Security Releases», Astra Security (22.10.2026)
Brotli ist ein Kompressionsformat von Google, das fast alle Browser und Webserver können. Wenn ein Server mit «Content-Encoding: br» antwortet, entpackt Node das automatisch. Der Fehler im Entpacker schreibt über das Ende eines Speicherbereichs hinaus. Damit kann ein Angreifer im schlimmsten Fall eigenen Code ausführen. Laut Advisory gibt es keinen Workaround, nur das Update.

Node.js · So beheben wir es

Unsere Nuxt-Projekte laufen auf Node.js: jetzt updaten

  Mit nvm, in 3 Befehlen

node -v
v24.14.0
betroffen 
nvm install 24.22.1
nvm alias default 24.22.1
node -v
v24.22.1
sicher
  Danach npm run dev neu starten und in WebStorm den Node-Interpreter auf 24.22.1 umstellen.

Wo trifft es uns?

  • Pokémon-Projekt: useFetch holt Daten von der PokeAPI. Beim Server-Rendering entpackt Node diese Antwort.
  • Ollama-Demo: spricht nur mit localhost, kleines Risiko
  • Online: Vercel, Netlify oder Docker müssen auch die neue Version nutzen
npm update hilft hier nicht. Der Fehler steckt in Node.js selbst, nicht in einem Paket aus node_modules.
Alte Versionen aufräumen: nvm ls zeigt z. B. noch v16 und v20 (beide ohne Updates), nvm uninstall 20.10.0
Auf diesem Mac lief Node 24.14.0, also betroffen. nvm hat 24.22.1 als «Latest LTS». Wichtig für die Klasse: Ein laufender Dev-Server benutzt weiter das alte Node, bis man ihn neu startet. Und npm audit findet diesen Fehler nicht, weil es nur Pakete prüft, nicht Node selbst. Wer in einem Projekt die Version festhalten will: eine Datei .nvmrc mit «24.22.1» und dann «nvm use» im Projektordner.
